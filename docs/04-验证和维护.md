# 验证和维护

## 测试入口

课程根目录：

```powershell
python -m unittest discover -s tests -v
```

固件目录：

```powershell
python -m unittest discover -s scripts/tests -v
python scripts/build_nailong.py --ota-url http://192.168.1.20:8003/xiaozhi/ota/
```

部分主机 C++ 测试需要 g++，MCP 序列化测试还需要首次构建下载的 cJSON 依赖；缺少时 unittest 会标记跳过。查看通过/失败/跳过数量，不把“跳过”算成已经验证。

后端保留上游 tests。完整后端测试需其独立 Python 3.10 环境与依赖；课程根测试只检查配置生成与地址/合并契约，不会加载大型语音模型或访问云端。

当前自动验证结果和真机边界见根目录 `VALIDATION.md`。如改动动作取消、音频状态或两端协议，应再次测试真实设备。

## 建议教学顺序

1. 看引脚和分区，建立一次原样构建。
2. 更换待机图，观察素材分区与字幕层。
3. 在云端和本地后端之间切换，观察 OTA 发现协议。
4. 修改人设，观察真实 MCP 调用与本地笑声。
5. 理解延迟工具结果与组合音频/行走。
6. 观察 FreeRTOS 队列、识别任务、按键事件和协作取消。

## 源码包维护

- 原个人工程继续留在课程目录之外，不把个人配置复制回来。
- `dependencies.lock` 固定固件依赖版本；SDK 固定为 5.5.5。不要只复制旧 build/ 来当可复现源码。
- 学生的 `.config.yaml`、环境变量、NVS 备份、下载权重和构建目录是本地数据，发布前排除。
- 后端默认 Dockerfile 依赖上游基础镜像；直接使用 server_latest 运行的是该远程镜像，不保证与这份快照完全相同。课程以源码启动为主，Docker 进阶按上游文档构建本地源码。
- 根目录没有嵌套 Git 历史，可在准备正式发布时从这里新建课程仓库。不要把个人工程的整个 Git 历史直接推送为课程仓库。
- 上游说明、版权和各组件许可证保留。素材的来源记录不能代替其授权记录。

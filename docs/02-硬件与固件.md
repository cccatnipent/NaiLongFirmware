# 硬件与固件实验

## 固定硬件范围

本课程的“通用”指同型号硬件上的不同机器。上游其它板型源码仍保留供学习，不能据此把本课程镜像烧到任意 ESP32 板。

| 外设 | GPIO |
|---|---|
| 左腿、右腿、左脚、右脚 | 17、39、18、38 |
| 屏幕 MOSI、CLK、DC、RST、CS、背光 | 10、9、46、11、12、3 |
| 麦克风 WS、SCK、DIN | 4、5、6 |
| 喇叭 DOUT、BCLK、LRCK | 7、15、16 |
| BOOT、充电检测 | 0、21 |

板型为 `nailong-otto`，手臂引脚均不连接，跳过摄像头探测。GPIO 唯一性由 `nailong_config.h` 的编译期断言检查。Flash 16MB / PSRAM 8MB，分区表 `partitions/v2/16m.csv`。

## 认识源码

| 文件 | 学习内容 |
|---|---|
| `scripts/build_nailong.py` | 选择课程变体、中文 MultiNet、自定义 OTA |
| `main/application.cc` | 主循环、听取/说话状态、BOOT 和本地命令事件 |
| `main/audio/wake_words/custom_wake_word.cc` | 区分 wake / stop 命令与置信度 |
| `main/boards/otto-robot/nailong_display.cc` | 图片场景及字幕/状态栏 |
| `main/boards/otto-robot/nailong_actions.cc` | 本地笑声、延迟完成 MCP、音频和行走并行 |
| `main/boards/otto-robot/otto_controller.cc` | 动作队列、工作任务、协作取消 |
| `main/boards/otto-robot/otto_movements.cc` | 舵机插值、摆动、可取消等待 |

FreeRTOS 已是 ESP-IDF 运行基础。本地命令检测与云端录音上行分别控制；回答时本地可识别“停下”，云端保持半双工。没有新增硬件回声参考。

## 设备身份与配置

每台设备用原厂 MAC；`board/uuid` 已有则沿用，没有则随机生成并保存。固件不包含固定 MAC/UUID 或身份迁移逻辑。Wi-Fi、舵机微调仍存 NVS。已有 xiaozhi.me 绑定不会因为刷通用版自动换绑。

个人特殊机器继续使用原个人工程，这份课程源码不承担其身份迁移。

## 素材实验

已经转换的素材位于 `main/boards/otto-robot/nailong_assets/`：九张 240×240 RGB565 小端图片、5秒单声道16kHz Ogg Opus。`nl_materials.json` 记录来源和哈希。

默认图使用原图 `9.raw`，大笑图使用 `2.raw`；其余七张每次回答随机选一张，避免连续重复。图片、字幕、网络和电量共存。

更换课程根目录 `Materials` 后，在固件目录运行：

```powershell
python scripts/prepare_nailong_materials.py --ffmpeg <ffmpeg路径> --laugh-seconds 5
python scripts/build_nailong.py --ota-url http://192.168.1.20:8003/xiaozhi/ota/
```

更新主程序和资源分区，不能只更新其中一份。素材来源/授权记录见根目录 THIRD_PARTY_NOTICES.md。

## 烧录与分区

| 分区 | 地址 | 大小 |
|---|---|---|
| NVS | 0x9000 | 0x4000 |
| OTA 数据 | 0xD000 | 0x2000 |
| PHY | 0xF000 | 0x1000 |
| 应用 ota_0 | 0x20000 | 0x3F0000 |
| 应用 ota_1 | 0x410000 | 0x3F0000 |
| 素材 | 0x800000 | 0x800000 |

同分区布局的已有设备，更新应用和资源可使用：

```powershell
python -m esptool --chip esp32s3 -p COM3 -b 115200 write_flash --flash_mode dio --flash_freq 80m --flash_size 16MB 0x20000 build/xiaozhi.bin 0x800000 build/generated_assets.bin
```

写到 ota_0 仅适用于启动槽仍选 ota_0 的设备；经历 OTA 后请按本机构建的完整 `idf.py flash` 流程重置 OTA 选择数据，或确认当前启动槽。升级前备份设备数据并核对布局。

构建产物中的 `merged-binary.bin` 从 0 写入会覆盖填充区内的 NVS；课程源码不提供任何设备的 Flash 备份作为公开镜像。
